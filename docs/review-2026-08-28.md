## Phase 2 smoke test findings (2026-08-28)

Ran for real against a disposable Debian 12 VM with Docker: `docker compose
build`, `squid -k parse`, `docker compose up`, and live traffic through the
proxy (real Basic Auth, real SNI-based splice/bump decisions, real
Crunchyroll API resolution, a real per-user show approval via the dashboard).
Four bugs were found and fixed, none of which any amount of static review or
the Tier-1 pytest suite could have caught -- all four are specifically about
how Squid itself behaves, not about the Python logic underneath it.

1. **`proxy/Dockerfile` installed `squid`, not `squid-openssl`.** Debian's
   plain `squid` package is built `--with-gnutls`, which does not support
   SSL-Bump at all -- `squid -k parse` failed immediately with `Unknown
   http_port option 'ssl-bump'`. `squid-openssl` is the exact same version,
   built `--with-openssl`, and is what this project's entire `ssl_bump`
   config depends on.

2. **`proxy/entrypoint.sh` never created `/var/lib/squid`** before calling
   `security_file_certgen -c -s /var/lib/squid/ssl_db`. Unlike
   `/var/spool/squid` and `/var/log/squid`, `squid-openssl` does not
   pre-create `/var/lib/squid`, and `security_file_certgen` does not create a
   missing parent directory -- every container start crash-looped on `Cannot
   create /var/lib/squid/ssl_db`.

3. **Every `external_acl_type` FORMAT string was missing an explicit `%DATA`
   macro** (S1, fails closed). Squid always appends `%DATA` to an
   `external_acl_type` FORMAT unless it's already present (documented
   behavior) -- so `sni_helper.py` and `authz_helper.py` were both
   registering `field_count` one short of what Squid actually sends. Every
   single request was rejected as a malformed line and fell through to
   `ssl_bump terminate step2 all` -- **the entire SNI/authz decision layer,
   the whole point of the project, never worked against a real Squid
   instance.** `basic_auth_helper.py` is unaffected (`auth_param basic` uses
   a different protocol). Fixed by adding `%DATA` explicitly to every
   `external_acl_type` FORMAT and bumping `field_count`/handler signatures
   in both helpers. Regression test: `tests/test_squid_conf_regressions.py`.

4. **`http_access allow step1`/`step2`, left bare, also grants access to the
   real *decrypted* HTTP request that follows a bump decision** (S1/S2,
   fails *open* -- the more serious direction). Squid's `at_step` state for
   a connection does not reset once `ssl_bump` reaches step2, so the first
   decrypted request is *also* evaluated with step2 still true, matching
   `http_access allow step2` before `authz_allowed` is ever reached. This
   completely bypassed per-domain, per-path, and per-show enforcement for
   every bump-mode request, including Crunchyroll: an authenticated user
   could load *any* show's page, approved or not. Confirmed directly --
   with the bare rule, an unapproved show's page loaded from Crunchyroll's
   real backend; qualified with `CONNECT` (`http_access allow CONNECT
   step1`/`step2`), the identical request was correctly denied, showed up
   on the Report page with an Approve button, and was correctly granted
   after clicking it. The decrypted inner request's method is never
   `CONNECT`, so this confines step1/step2 to the tunnel/negotiation phase
   exactly as intended. Regression test (structural, not behavioral --
   this class of bug can only truly be caught by running real Squid):
   `tests/test_squid_conf_regressions.py`.

With all four fixed, the full loop was verified end-to-end on the VM: proxy
auth, a global splice domain (`google.com`), an unconfigured domain
correctly default-denied, a Crunchyroll path-allowlisted page, an unapproved
show blocked and logged, one-click Approve from the Report page, and the
same show subsequently loading successfully.

A fifth bug (2.8, `basic_auth_helper`'s percent-decoding assumption -- also
a real, previously-unverified bug, not just an untested claim) was found and
fixed the same way once a live Squid instance was available; see its row in
the resolution table above.

**Still open:** a real device (CA cert trust + actual playback) and `%>a`
client-IP behavior under this specific VM's networking.

## S1 — Will-it-work blockers

### 1.1 The LAN source-IP check fails under Docker bridge networking
`sni_helper.handle_splice` and `authz_helper.decide` both call
`matching.ip_in_configured_lan(client_ip)`, where `client_ip` is Squid's
`%>a` (the TCP peer address). With the published-port bridge setup in
`docker-compose.yml` (`ports: ["3128:3128"]`), the proxy container does **not**
see the real LAN client IP:

- **Docker Desktop (Windows/Mac — your platform):** the container sees the
  Desktop VM's gateway (e.g. `192.168.65.1` / `172.17.0.1`). Always.
- **Linux + `userland-proxy=true` (historical default):** container sees the
  `docker0` gateway (`172.17.0.1`).
- **Linux + `userland-proxy=false`:** real client IP is preserved.

Consequences on Docker Desktop:
- every `splice`-mode site → `handle_splice` returns `False`, logged as
  `outside_lan` → **all host-only sites blocked**.
- every `bump`-mode site (Crunchyroll) → `decide` returns `False`,
  `outside_lan` → **Crunchyroll blocked**.
- Net: nothing loads until `local_network` is widened to include the Docker
  gateway subnet — at which point the check accepts every device that can
  reach the port, so it provides no security.

**Options:**
- **A (recommended for a real deployment):** run the proxy with
  `network_mode: host` on a Linux box; drop the `ports:` mapping. Real client
  IPs, check works as designed. Not available on Docker Desktop.
- **B:** treat per-user proxy auth as the sole access control (it already is —
  the password is what gates a user). Make `ip_in_configured_lan` a soft
  check: if the resolved client IP is a private/Docker address, skip the LAN
  gate instead of failing closed. Document that `LOCAL_NETWORK` is
  belt-and-suspenders, only meaningful with host networking.
- **C:** keep as-is but document loudly that `LOCAL_NETWORK` must be set to the
  Docker bridge subnet on Desktop, and that it is not a real network ACL there.

Decision needed from the owner before I change code here.

### 1.2 Playback/token host `crunchyrollsvc.com` is never configured as a domain
`cr_urls.PLAYBACK_URL_RE` explicitly matches
`cr-play-service.prd.crunchyrollsvc.com/v1/...`, and `GUARDED_MARKERS`
includes `"cr-play-service"` — but no row in `seed_defaults.py` matches
`crunchyrollsvc.com`. `matching.find_domain` will not map that host to the
Crunchyroll bump domain (`crunchyroll\.com` is not a substring of
`crunchyrollsvc.com`), so such requests hit the `ssl_bump terminate step2 all`
catch-all.

- If current Crunchyroll web playback uses that host for manifests/tokens,
  **approved shows will not play** (connection terminated).
- If it only uses `www.crunchyroll.com/playback/...`, the second alternative
  of `PLAYBACK_URL_RE` and the `"cr-play-service"` marker are dead code.

**Fix:** confirm which host current CR uses (watch an episode with devtools
open). If the svc host is used, seed it:

```python
conn.execute(
    "INSERT OR IGNORE INTO domains (pattern, mode, kind, is_global, note, created_at) "
    "VALUES ('crunchyrollsvc\\.com', 'bump', 'crunchyroll', 1, 'Crunchyroll playback/token service', ?)",
    (db.now_iso(),),
)
```
Otherwise delete the svc alternative from `PLAYBACK_URL_RE` and the marker.

### 1.3 Untested Squid feature combination (carried from README)
`external_acl_type` with `%ssl::>sni` at `SslBump2`, `ssl_bump terminate`, and
Basic auth layered on ssl-bump — each is standard, the combination has never
run against a real Squid (Debian bookworm ships Squid 6.x). This is the
single biggest unknown. The test plan below starts here.

## S2 — Bugs and security

### 2.1 Domain patterns are matched unanchored — whitelist bypass with registrable domains
`matching.find_domain` does `re.search(row["pattern"], hostname, re.IGNORECASE)`.
Seeded patterns like `jsdelivr\.net`, `akamaized\.net`, `googleapis\.com`,
`google\.com` are substrings, not anchored suffixes. So:

- `evil-jsdelivr.net` — registrable — matches the global `jsdelivr\.net` row →
  **spliced through, unfiltered, for every user**.
- `crunchyroll.com.attacker.example` matches `crunchyroll\.com`.
- Any FQDN containing an allowed pattern as a substring is allowed.

This defeats the core guarantee of the proxy. **Fix:** match against the host
as an anchored domain suffix, e.g. treat each stored entry as a hostname (or
hostname regex) and test `re.search(r"(?:^|\.)(?:" + pattern + r")$", host, I)`,
or store plain domains and do explicit label-wise suffix comparison. Also
anchor the auto-added pattern in `dashboard.approve_from_report`
(`re.escape(row["domain"])` is currently stored unanchored too).

### 2.2 `crunchyrollcdn.com` is seeded twice — ends up `splice`, not `trusted`
`seed_defaults.py`: `crunchyrollcdn\.com` is in **both** `GLOBAL_SPLICE_DOMAINS`
(line 37) and `TRUSTED_DOMAINS` (line 52). `pattern` is `UNIQUE` and both
inserts are `INSERT OR IGNORE`; `seed()` inserts the splice list first, so the
`trusted` insert is silently dropped. Result: raw video-CDN traffic is
host-checked and logged per user instead of passing through untouched —
contradicts the stated design ("nothing per-user to decide"). **Fix:** remove
`crunchyrollcdn\.com` from `GLOBAL_SPLICE_DOMAINS` (keep it in `TRUSTED_DOMAINS`).

### 2.3 No CSRF protection on the dashboard
Every state change is a plain `POST` form with no token. The dashboard uses
HTTP Basic auth, so a browser that has authenticated once will attach
credentials to a cross-site form POST automatically. If the dashboard is bound
to `0.0.0.0` (an option in `setup.sh`) and a parent has it open, a page loaded
by anyone else on the LAN can POST to `/users/add`, `/domains/add`,
`/settings/admin`, etc. **Fix:** add a per-session CSRF token (Flask-WTF or a
hand-rolled signed token), or at minimum check `Origin`/`Referer` on POST and
bind to `127.0.0.1` by default (it already defaults to loopback — keep it, and
document the risk of `0.0.0.0`).

### 2.4 Dashboard container runs as root and shares the SQLite volume with the `proxy` user
`dashboard/Dockerfile` sets no `USER`, so it runs as root and creates
`/config/parental_proxy.db` (+ `-wal`, `-shm`) as `root:root`. The proxy
entrypoint does a one-time `chown -R proxy:proxy /config`, but SQLite in WAL
mode recreates `-wal`/`-shm` on checkpoint/reopen; if the root dashboard
recreates them, the `proxy`-user helper processes can hit
`attempt to write a readonly database` / lock errors intermittently. **Fix:**
run both containers as the same UID (add `user:` to compose, or a `USER` line
matching Squid's `proxy` uid), or put both in a shared group with group-write
+ a `umask 002`.

### 2.5 `CONNECT` is allowed to any port
`squid.conf.template` replaces Squid's default with `http_access allow CONNECT`
and no `Safe_ports` / `SSL_ports` restriction. An authenticated user can open a
CONNECT tunnel to any `host:port`. In practice the `ssl_bump` chain terminates
anything without a matching SNI (including non-TLS tunnels), so this is largely
contained — but it's a deviation from a hardened config and worth restoring:

```
acl SSL_ports port 443
http_access deny CONNECT !SSL_ports
```

### 2.6 Hardcoded anonymous Crunchyroll client credential is a single point of failure
`cr_api.ANON_BASIC_CREDENTIAL = "Y3Jfd2ViOg=="`. If Crunchyroll rotates the
anonymous web client id, `_refresh()` raises, `resolve_series_ids` returns
`None`, and `_decide_crunchyroll` fails closed → **all playback of not-yet-
resolved shows breaks**. Already-resolved shows keep working for
`POSITIVE_TTL_SECONDS` (30 days) from cache. Mitigations: lengthen positive
TTL further, serve stale-on-error for positive cache hits, and surface a
dashboard warning when token refresh fails.

### 2.7 No regex validation on `pattern` input (domains and paths)
`add_domain` / `add_path` store whatever string is submitted. `find_domain` /
`path_allowed` swallow `re.error` with `continue`, so a typo'd pattern
**silently never matches** — the admin gets no feedback and the rule appears to
"not work". A pathological pattern (catastrophic backtracking) would hang the
Squid helper for every user on the LAN (`ttl=0` → invoked per request).
**Fix:** `re.compile()` the pattern at submit time and reject with a flash
message on `re.error`; consider a length cap and a `regex`-module timeout in
the helpers.

### 2.8 `basic_auth_helper` does not URL-decode its input
The other two helpers `urllib.parse.unquote` their `external_acl_type` fields;
`basic_auth_helper` deliberately does not (`split(" ", 1)` only). The docstring
says classic Basic doesn't percent-encode — true historically, but confirm it
against Squid 6 with a password containing a space and a `%`. `add_user`
already restricts usernames to `[A-Za-z0-9_.-]+`, so only the password is at
risk. Low severity; verify during testing.

## S3 — Minor bugs / hardening

- **CA cert extensions:** `entrypoint.sh` generates the CA with
  `openssl req -x509` and no explicit `-addext "basicConstraints=critical,CA:TRUE"`.
  Debian bookworm's openssl 3 config normally adds it, but Squid's dynamic cert
  generation *requires* `CA:TRUE`. Make it explicit so this doesn't depend on
  the base image's `openssl.cnf`:
  `-addext "basicConstraints=critical,CA:TRUE" -addext "keyUsage=critical,keyCertSign,cRLSign"`.
- **Flask dev server in production:** `dashboard.py` calls `app.run()` — single
  threaded, not for production per Flask's own warning. Every blocked bump
  request redirects a browser to `/blocked` on this server. Use `waitress`
  (pure-Python, Windows-friendly) or `gunicorn`.
- **`DASHBOARD_PASSWORD` stays mandatory forever:** compose declares it
  `${DASHBOARD_PASSWORD:?...}` even though `bootstrap_admin` ignores it after
  first run. Make it optional post-bootstrap or document that `.env` must keep
  a placeholder.
- **`squid.conf` has no `cache deny all`:** with no `cache_dir` the risk is
  low (memory cache only, keyed by URL + respects auth), but an explicit
  `cache deny all` removes any chance of cross-user response reuse on a bumped
  connection.
- **`setup.sh` IP autodetection is Linux-only** (`ip route get`). On Windows
  Git Bash it silently falls back to `192.168.1.0/24`. Add a `hostname -I` /
  `ipconfig` fallback or just prompt.
- **`access_log` dedupe query** filters on `series_id IS ?` which isn't in
  `idx_access_log_dedupe`. Fine at home scale; note it if the log ever grows.
- **`user_detail` "Sites" link** points to the generic `/domains` page, not a
  filtered view — the "N assigned" count and the page you land on don't line
  up. Cosmetic.
- **`add_show` never resolves the real series title** (only `approve_from_report`
  does, via `fetch_series_title`). The name is derived from the URL slug and
  the "auto-filled" placeholder implies JS that doesn't exist. Cosmetic.

## S4 — Streamlining (no behaviour change)

- **Dead code in `cr_api.py`:** `episodes_of_series`, `_entry_ids`,
  `SEASONS_URL`, `EPISODES_URL` are referenced nowhere outside `cr_api.py`
  itself. ~35 lines. Delete unless there's a planned use.
- **Duplicated Squid-helper scaffolding:** `basic_auth_helper.main`,
  `sni_helper.main`, `authz_helper.main` are the same stdin-loop / field-split /
  unquote / dispatch / flush pattern. Extract
  `common/squid_helper.py: run(field_count, handler)` — one place to get the
  protocol right, ~40 lines saved.
- **`logging_util`** recomputes an ISO timestamp cutoff with its own
  `strftime`; add `db.iso_secs_ago(n)` and reuse (`db.now_iso` is already the
  sibling helper).
- **`dashboard.fetch_series_title`** hand-rolls a CMS `/objects/` fetch that
  `cr_api.SeriesResolver` already does. Expose `cr_api.series_title(series_id)`
  and call it from both places.
- **`matching.find_domain`** recompiles every stored pattern on every request
  (`ttl=0`). Cache compiled patterns per helper process, keyed by the pattern
  string, invalidated on a cheap `SELECT COUNT(*), MAX(id)` check. Only worth
  it if request volume is higher than a typical home LAN.
- **`cr_api.series_id_of`** has four fallback branches; `season_metadata`,
  top-level `series_id`, and `type == "series"` may all be unreachable for the
  `/objects/` response shape. Verify against a real payload and drop the ones
  that can't fire.
